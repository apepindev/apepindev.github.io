Dotfiles part 4: halving zsh startup time

Swapping nvm for fnm and lazy-loading thefuck cut a new shell from about 1.5s to 0.8s.

Part 4 of my dotfiles series.

A new shell took about 1.5 seconds to start. After two changes it now takes about 0.8 seconds. As well as slimming down the oh-my-zsh plugins, these helped a lot too;

nvm to fnm#

nvm (node version manager) is a shell script. Sourcing it on every shell start was the largest single cost. fnm is a compiled Rust binary that does the same job:

command -v fnm &> /dev/null && eval "$(fnm env --use-on-cd)"

--use-on-cd switches Node version when a directory has a .nvmrc or .node-version file for convenient version switching.

Lazy-loading thefuck#

thefuck --alias starts Python to print the alias, about 130ms on every shell start. The alias is rarely needed in a given shell. A small function defers the cost to first use:

if command -v thefuck &> /dev/null; then
  fuck() {
    unfunction fuck
    eval "$(thefuck --alias)"
    fuck "$@"
  }
fi

On the first call, the function deletes itself, defines the real alias, and runs it with the same arguments. Later calls go straight to the alias.

Pointing Starship at its config#

Starship reads ~/.config/starship.toml by default. The symlink lives at ~/.config/starship/starship.toml, so Starship was running without my config. One export fixed it:

export STARSHIP_CONFIG="$HOME/.config/starship/starship.toml"
